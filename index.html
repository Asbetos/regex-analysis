Can a simple word search cut the AI's workload?

Every statute section currently goes to an AI model to be labelled, which is slow and expensive. We tested whether a plain keyword search can throw out the clearly-irrelevant sections first, so the model only reads the plausible ones — and measured how many correct answers that costs.

How we tested it

The earlier attempt at this chose its keywords by looking at the answers and then graded itself on those same answers — so its scores meant nothing. We fixed that.

  1. Hide some laws. Split into 70% "study" and 30% "exam". Whole laws move together, never split — sections of one act reuse each other's wording, which would leak answers.
  2. Choose the words using only the study set. The exam set is never consulted.
  3. Grade once on the exam set. No peeking, no second attempts.
  4. Repeat 20 times with different splits, so no single lucky split decides the answer.

Does the filter still work on older laws?

Drafting language changes over time, so a word list built on recent statutes might fail on 1940s ones. We tested this by hiding one whole decade at a time, building the filter on the other seven, then testing on the hidden decade.

The answer is yes. Both filters transfer across decades — every decade stays above 91%. The weakest are Q1's 1940s and 1980s (both 93.8%) and Q6's 2020s (91.8%), and the 2020s has only 49 relevant sections so its figure moves easily. Note there are no 1950s laws in the dataset; those volumes were never coded.

Why we did not build a separate filter per decade

The obvious alternative is one tailored filter for each decade. We tried it, and it is worse — not because eras differ, but because a single decade has too few examples to learn from.

The tell is how much it discards, not its hit rate. A decade-specific filter often looks fine on hit rate, but only because it shrinks to one or two very common words that let nearly everything through — so it saves almost nothing. It also fails to find any workable word list at all in a large share of attempts (below).

Two things worth knowing about the method

Why laws move together in the split

A single act can contain hundreds of sections that reuse each other's wording, and they usually share the same label. If some went into the study set and others into the exam set, the filter would be graded partly on text it had already seen. Keeping each act wholly on one side removes that. We checked how much this mattered by also running the naive version — the difference was within noise, so this is insurance rather than the thing that fixed the earlier work.

Applying the filter later needs no grouping

Grouping by law was only about grading honestly. The filter itself is a fixed list of words with no memory — on a new volume you run it on each section independently.

What is still outstanding

One confirmation run on a freshly coded volume with the word list fixed in advance. The three volumes used for the cost measurement were held out from building the filter, but they have been examined several times across this project, so they are not completely fresh. The recommended word list is stable — re-deriving it with those volumes fully excluded returns the identical list — so this is confirmation rather than an open risk.
